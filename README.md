# Витрина цитатника

Сервис-«витрина» между каталогом цитат и читателями. Держит у себя копию
каталога, отдаёт цитаты по одной и переживает недоступность каталога,
не заваливая его запросами.

## Что делает

Каталог — чужая система, обслуживающая всю компанию. Читателей к нему
не пускают, между ними стоит витрина. Каталог присылает витрине полный
снимок раз в несколько минут; между снимками витрина может прочитать
из каталога одну цитату по её идентификатору.

Витрина:

- принимает полный снимок каталога потоково (до 340 000 записей, до ~110 МБ
  в одном запросе), не загружая тело целиком в память;
- держит состояние в памяти процесса (внешние БД, кэши и брокеры не
  используются);
- отдаёт читателю цитату, помечая источник ответа заголовком
  `X-Source: LOCAL | CATALOG`;
- перечитывает данные из каталога, если они устарели (TTL 60 секунд);
- уважает `Retry-After` при ответе каталога `503`;
- при недоступности каталога перестаёт к нему обращаться на время
  (circuit breaker) и отвечает из локальной копии;
- укладывается в лимиты: 256 МБ памяти, 0.5 CPU, ≤ 64 процессов,
  `/tmp` 64 МБ.

## Стек

- Python 3.12
- FastAPI
- Uvicorn
- httpx
- Docker

## Запуск

### Локально

```bash
python -m venv venv
source venv/bin/activate    # Windows: .\venv\Scripts\Activate.ps1
pip install -r requirements.txt
uvicorn app.main:app --host 0.0.0.0 --port 8000
```

### В Docker

```bash
docker build -t quotes .
docker run --rm -p 8000:8000 \
  --memory=256m --cpus=0.5 --pids-limit=64 \
  --tmpfs /tmp:size=64m \
  quotes
```

После старта сервис слушает порт `8000`.

## Контракт

### `GET /health`

```json
{"status": "healthy"}
```

Отвечает сразу после старта и всё время работы — даже до того, как витрине
сообщили адрес каталога.

### `POST /catalog/source`

```json
{"url": "http://catalog.internal:9000"}
```

Ответ:

```json
{"source": "http://catalog.internal:9000"}
```

Адрес можно сообщить повторно — действует последний.

### `POST /import`

Приём полного снимка каталога. Тело:

```json
{"quotes": [
  {"id": "q-0000001", "author": "Марк Аврелий", "text": "…", "tags": ["стоицизм"], "year": 170, "lang": "ru"}
]}
```

Ответ:

```json
{"imported": 340000, "dropped": 120}
```

- `imported` — сколько записей пришло в снимке;
- `dropped` — сколько цитат покинуло каталог.

Некорректное тело → `400`. Состояние витрины при этом не меняется.

### `PUT /catalog/{quote_id}`

Редакция добавляет или заменяет одну цитату.

```json
{"author": "Марк Аврелий", "text": "…"}
```

- `author` — от 1 до 200 знаков;
- `text` — от 1 до 16384 знаков.

Ответ `200`:

```json
{"id": "q-0000001", "author": "Марк Аврелий", "text": "…"}
```

Нарушение границ → `422`. Такая запись актуальна по определению — читателю
она отдаётся сразу, без обращения в каталог.

### `DELETE /catalog/{quote_id}`

Редакция снимает цитату с публикации.

```json
{"deleted": true}
```

Если цитаты нет → `404`. Снятая цитата читателям не отдаётся до следующего
снимка — даже если в каталоге она ещё есть.

### `GET /quotes/{quote_id}`

Чтение цитаты читателем. Ответ содержит запись целиком.

```json
{"id": "q-0000001", "author": "Марк Аврелий", "text": "…", "tags": ["стоицизм"], "year": 170, "lang": "ru"}
```

Заголовок `X-Source`:

- `LOCAL` — отдано из того, что витрина держит у себя;
- `CATALOG` — за этим ответом витрина обращалась в каталог.

Если цитаты нет ни у витрины, ни в каталоге — `404`. Отрицательный ответ
не кэшируется: редакция заводит цитаты постоянно, и читатель по свежей
ссылке должен увидеть цитату сразу.

### `GET /stats`

```json
{
  "served_local": 10423,
  "served_from_catalog": 512,
  "catalog_reads": 96,
  "evictions": 148,
  "local": 63,
  "bytes": 516159,
  "catalog": 340000
}
```

| Поле | Значение |
|------|----------|
| `served_local` | сколько ответов читателям витрина отдала, не обращаясь в каталог |
| `served_from_catalog` | сколько ответов читателям потребовали обращения в каталог |
| `catalog_reads` | сколько запросов витрина отправила в каталог |
| `evictions` | сколько записей витрина вытеснила у себя, не считая ушедших из снимка |
| `local` | сколько записей витрина держит наготове сейчас |
| `bytes` | сколько байт они занимают сейчас |
| `catalog` | сколько цитат витрина знает сейчас |

`served_from_catalog` и `catalog_reads` считаются независимо и совпадать
не обязаны.

## Как это устроено

### Хранение

Записи хранятся как **JSON-строки** в `OrderedDict` — так на 340 000 записей
уходит ~146 MiB вместо ~237 MiB при хранении Python-словарей. Это
принципиально: лимит памяти 256 МБ, и хранение словарей вплотную подводит
к OOM.

Рядом — два вспомогательных словаря: `_meta` (id → время кэширования, для TTL)
и `_deleted` (id → время удаления, для `DELETE`).

### Приём снимка

Снимок разбирается **потоково** — витрина читает `request.stream()` по чанкам
и разбирает JSON-объекты по одному. Список всех записей в памяти не
собирается. Это позволяет принять снимок до 110 МБ, уложившись в 256 МБ.

Для корректной работы с UTF-8 используется инкрементальный декодер —
многобайтные символы, разрезанные границей чанка, собираются правильно.

### Снимок: две фазы

Импорт снимка идёт в две фазы:

1. `begin_snapshot()` — ставит метку времени;
2. по одной записи через `insert_from_snapshot()` с этой меткой;
3. `finish_snapshot()` — удаляет всё, у чего метка старая (то есть цитаты,
   которых нет в новом снимке), возвращает `dropped`.

Если тело оказалось невалидным, `rollback_snapshot()` удаляет всё, что успело
вставиться с новой меткой, и старое состояние остаётся нетронутым. Поэтому
`POST /import` с мусором даёт `400` и **не теряет данные**.

### Работа с каталогом

- **TTL 60 секунд** — данные из каталога старше минуты считаются устаревшими
  и перечитываются.
- **`Retry-After`** — при `503` от каталога витрина не обращается к нему
  раньше указанного срока.
- **Circuit breaker** — после нескольких подряд ошибок обращения к каталогу
  (таймауты, `503`) витрина перестаёт к нему ходить на время. Это защищает
  каталог: чем плотнее в него стучат, тем дольше он поднимается.
- **Один параллельный запрос** — витрина не занимает несколько мест
  в каталоге одновременно.

### LRU-эвикция

Если суммарный размер записей превышает `MAX_BYTES`, вытесняются самые
давно использованные. Счётчик `evictions` учитывает только эти вытеснения,
не считая ушедших из снимка.

## Проверка

### Быстрый smoke-тест

```bash
curl http://localhost:8000/health
curl -X POST http://localhost:8000/catalog/source \
     -H "Content-Type: application/json" \
     -d '{"url":"http://catalog.internal:9000"}'
curl -i http://localhost:8000/quotes/q-0000001
curl http://localhost:8000/stats
```

### Проверка лимитов

```bash
docker run --rm -p 8000:8000 \
  --memory=256m --cpus=0.5 --pids-limit=64 \
  --tmpfs /tmp:size=64m \
  quotes

docker stats --no-stream
```

При 340 000 записей витрина занимает около 146 MiB памяти.
